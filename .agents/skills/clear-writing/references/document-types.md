# Document Types

Use these as information-flow models, not rigid templates.

## Technical design

Typical flow:

1. Context
2. Problem
3. Goals
4. Non-goals
5. Constraints
6. Alternatives considered
7. Proposed design
8. Trade-offs
9. Risks
10. Rollout / migration
11. Open questions

Put the decision-driving constraints before implementation details.

## Investigation

Typical flow:

1. Question or problem
2. Current state
3. Scope
4. Evidence
5. Findings
6. Hypotheses
7. Unknowns
8. Conclusion
9. Next actions

Keep evidence separate from interpretation when that distinction matters.

## Incident report

Typical flow:

1. Summary
2. Impact
3. Detection
4. Timeline
5. Technical cause
6. Contributing factors
7. Recovery
8. Corrective actions
9. Follow-up

Avoid blame-oriented language.

Separate root cause from contributing factors.

Do not call something a root cause unless the evidence supports it.

## ADR / decision record

Typical flow:

1. Context
2. Decision drivers
3. Options
4. Decision
5. Rationale
6. Consequences
7. Follow-up

Do not present rejected options as if they were never viable.

## Proposal

Typical flow:

1. Problem
2. Proposed change
3. Expected benefit
4. Trade-offs
5. Risks
6. Implementation
7. Decision required

Distinguish expected benefit from measured benefit.

## Runbook

Typical flow:

1. Purpose
2. Preconditions
3. Procedure
4. Validation
5. Failure handling
6. Rollback
7. Escalation

Make actions unambiguous.

Put warnings before the step that can cause damage.

## Technical report / analysis

Typical flow:

1. Executive summary
2. Scope
3. Method
4. Observations
5. Interpretation
6. Limitations
7. Recommendations

Separate measured observations from interpretation.
